# Phase 0 — offline technical-readiness manifest

Generated by the offline importer (`scripts/offline_importer.py`). First built 20 September 2026 (session 1: RTI Act sections 6/8); strengthened and broadened the same day in a **second pass** (session 2: defect review, Environment Act sections 3/5A, Kerala date investigation, RTI Rules OCR assessment, access-response checklist); further strengthened the same day in a **remediation pass** (session 3, responding to `docs/phase-0/INSPECTION_FOLLOWUP.md`: binds admission to reviewed extracted-text digests, fixes manifest-restoration state, retains the previously-missing RTI page-10 render — see "Remediation, 2026-09-20" below). Operates only on retained fixtures under `data/discovery/` and hand-authored review decisions under `data/review/`. No network requests were made in any pass. This manifest states what is technically ready offline; it does **not** grant, imply, or depend on India Code's response to the user's pending 20-Act access request. See [access status](ACCESS_AND_REUSE.md#access-request-status).

Reproduce with:

```sh
python3 scripts/build_phase0_artifacts.py
python3 scripts/verify_phase0.py
python3 scripts/offline_importer.py --fresh
python3 scripts/verify_offline_import.py
```

## Second-pass defect review of the importer itself

Before broadening scope, the existing importer and its regression suite were audited critically. Defects found and fixed (all covered by new regression checks so they cannot silently regress):

1. **Hardcoded capture set** — `import_all` listed RTI's two capture names by hand; adding a second Act's review records would have raised a `KeyError`. Now derived dynamically from every loaded review record's declared captures.
2. **Hardcoded structured-HTML capture name** — the HTML extraction path ignored the review record's own declared `capture` field and always re-read `rti-sections-page-0`, plus had no check that a matched section record actually belonged to the right Act/UUID. Fixed to use the declared capture and to verify the specific section-item UUID when given.
3. **No extraction-method-version enforcement** — review records declared an `extraction_method_version`, but the importer never compared it to the code's current version, so a future code change could silently apply unreviewed extraction logic to an old approval. Now compared; a mismatch invalidates admission (`invalidated_extraction_method_changed`).
4. **No footnote-consistency check** — a review record's `footnotes_present` flag was stored but never checked against what extraction actually found. Now a declared-but-missing (or found-but-undeclared) footnote invalidates admission rather than silently serving text without it, or silently exceeding what was reviewed.
5. **Global reviewer mis-attribution** — `review_decisions` loaded a single hard-coded `reviewer.json` and stamped it onto every provision; this would have silently mis-attributed the Environment Act's second-pass review to the session-1 reviewer. Now each review record's own `reviewer_ref` is resolved and cached per reviewer file.
6. **Incomplete idempotence check** — the existing idempotence test compared only the `documents` and `provisions` tables, missing the `excerpts` table (which is rebuilt with DELETE+INSERT, a different code path). Now all five tables are compared.
7. **Stale readiness-manifest scope strings** — the manifest generator's `scope` text and its `documents_known_but_unreviewed` list both hard-coded `"rti-2005"`, which would have mislabeled the Environment Act as "known but unreviewed" once it had admitted provisions. Both are now derived from the actual set of reviewed act slugs.
8. **Watermark-removal risk, checked rather than assumed** — before trusting the existing "IndiaCode" watermark-stripping rule on a second document, it was run against `environment-1986.txt` and produced 65 matches, all independently confirmed (by inspecting surrounding context) to be genuine mid-sentence watermark artifacts, not legitimate short lines. A dedicated regression test now also proves, with constructed near-misses, that the rule cannot strip a real short line merely for sharing a token, an indentation level, or a substring with the watermark pattern — see check #13 below.

Both raw observations (14 and 25 August 2026) are preserved. The canonical enactment date is now resolved to **14 August 2026**, based on retained-PDF evidence (the Act's own printed assent-date bracket) cross-calibrated against the identical convention in the RTI Act's PDF, where it independently matches known metadata. One genuine residual gap remains and is disclosed: the live collection-listing UI's exact internal field mapping was never independently re-captured (only narratively described during Phase 0), so the *reason* the listing displayed 25 August cannot be confirmed with certainty, only explained plausibly. **This resolution does not lift the Act's quarantine** — it remains outside the searchable slice regardless.

- All other 29 RTI sections, all other 35 Environment Act sections, and all provisions of the other eight candidate Acts — known at document level only (title, dates, source URLs, manifest metadata), with no reviewed or admitted provision text. They must not be treated as searchable.

## Remediation, 2026-09-20: binding admission to reviewed output and fixing manifest-restoration state

A follow-up inspection (`docs/phase-0/INSPECTION_FOLLOWUP.md`) found two gaps in the invalidation
mechanism above and both are now fixed; see `docs/phase-0/INDEPENDENT_REVIEW.md`'s dated remediation note
for the full history. In brief:

- **Admission is now bound to the reviewed extracted text itself**, not only to source bytes and a
  manually maintained extraction-version label. Each of the four review records now carries an
  `expected_output` block (`body_text_sha256`, and `footnote_text_sha256` or the explicit sentinel
  `"no-footnote-expected"`), established during this remediation session by re-running the current
  extraction against the same retained bytes and cross-checking the result against that record's own
  evidence — **not** claimed to have existed during the original review. At import time, freshly extracted
  output is compared against these digests before admission; a mismatch invalidates the provision
  (`invalidated_body_text_changed` / `invalidated_footnote_text_changed`) and removes its excerpt; a missing
  baseline refuses admission (`invalidated_missing_expected_digest`) rather than defaulting to admitted.
- **Manifest restoration now clears `removed_from_manifest`** when a document reappears in the manifest,
  instead of leaving that flag stuck at `1` forever after a temporary removal. The readiness manifest JSON
  now also exposes `documents_removed_from_manifest` explicitly rather than only implying removal through
  absence.
- The previously-unretained RTI section 8 page-10 render has been regenerated and retained at
  `data/discovery/derived/rti-2005-page-10.png`, with its own generation provenance disclosed in
  `data/review/reviewer-remediation.json` (it confirms today's page content; it does not retroactively
  prove the original session's inspection).

Six new regression checks cover both fixes, including full remove-then-restore round trips and unchanged
source-bytes-but-changed-output scenarios that the pre-remediation suite could not catch.

## Regression coverage

`scripts/verify_offline_import.py` runs the following checks against the retained fixtures (run the script
directly for the current exact count — new checks are added as gaps are found, so a hardcoded number here
would go stale, as one already had before this remediation):

1. The RTI-001 substantive mismatch is flagged and the excluded HTML wording never reaches admitted text.
2. The section 8 amendment footnote is preserved and kept distinct from the body text.
3. All four admitted provisions' PDF anchors are bound to the exact retained PDF hash (both Acts).
4. Kerala's conflicting dates both survive, with the canonical date traceable to an explicit, evidenced conflict-record resolution — and the Act stays excluded from the slice regardless.
5. The date-resolution mechanism is proven generic (not a Kerala special case) using a synthetic unresolved-conflict fixture, which correctly stays null.
6. RTI Rules OCR text is excluded and cannot be auto-admitted.
7. An unverifiable/incomplete source (simulated hash mismatch) is invalidated rather than treated as verified content.
8. Repeated imports are idempotent across every table (documents, provisions, review_decisions, conflicts, excerpts): no duplicate rows, no drift.
9. A simulated changed source hash invalidates a previously admitted provision, and restoring the correct bytes re-admits it without duplication.
10. An excerpt resolves exactly back to a byte-offset slice of its admitted source text.
11. Every unreviewed RTI section, every other Environment Act section, and every other candidate Act stays unadmitted despite being known at document level.
12. The agent review (both sessions) is explicitly disclosed and never presented as independent legal-expert review.
13. The Environment Act slice is admitted with its full nested-clause / amendment-bracket structure intact, and is explicitly labeled PDF-only.
14. The watermark-stripping rule is proven scoped: true positives are removed; constructed near-misses (insufficient indentation, a token merely embedded in a longer line, a token followed by punctuation) all survive; and the rule's actual matches against both retained PDFs' extracted text are confirmed to be exactly the five expected watermark tokens.
15. A changed extraction-method version invalidates a prior admission rather than silently applying it to text the reviewer never checked.
16. A declared-but-missing footnote invalidates admission rather than silently serving text without it.
17. Every provision's declared known-conflict references resolve to a matching conflict record whose own scope names that provision.
18. Dev-query versions are honest: v1 is preserved byte-for-byte, v2 only extends coverage to newly admitted provisions, and no relevance score is ever invented.
19. Each provision's stored reviewer attribution matches the reviewer who actually reviewed it (catches the session-1→session-2 mis-attribution defect described above).
20. Removing a review record from an existing (non-fresh) database invalidates its provision — admission status, body text, footnote text, and its excerpt — and restoring the record re-admits it without duplication.
21. Removing an Act from the manifest flags its stale document row (`removed_from_manifest`) on an existing database rather than leaving it silently looking current.
22. A full remove-then-restore round trip on one existing database (Environment Act removed, reimported, restored, reimported, reimported again) clears `removed_from_manifest`, re-admits its provisions, keeps readiness output (`documents_removed_from_manifest` / `documents_known_but_unreviewed`) consistent, and stays duplicate-free across a repeated import.
23. A body-text change with **unchanged** source bytes and extraction-method-version — reproducing the exact scenario in `docs/phase-0/INSPECTION_FOLLOWUP.md` Finding 1 — is caught by the `expected_output` digest comparison, invalidates admission, leaves no stale excerpt, and restoring the approved output re-admits without duplication.
24. A footnote **wording** change (the footnote is still present, so the missing-footnote check alone cannot catch it) is caught by the same digest comparison and invalidates admission.
25. A provision whose review record has no `expected_output` baseline at all is refused admission (`invalidated_missing_expected_digest`) rather than defaulting to admitted just because its source hash and extraction version happen to match.

These are technical-readiness checks. They say nothing about retrieval quality (no search implementation exists yet — see [Phase 1](../../PHASES.md#phase-1--build-the-first-working-search-engine)) and nothing about public-indexing permission (see [ACCESS_AND_REUSE.md](ACCESS_AND_REUSE.md)).
